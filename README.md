# tsuzuri-fumiko（綴文子）

日本語ブログの「統合評価 → AI清書 → 修正確認」を行うAgent Skillです。原稿を110点満点で評価し、指摘をもとに清書した後、修正の効果と新しい問題の有無を確認します。

原意、論理、事実の範囲、書き手の声を保ちながら、必要な箇所を直します。新規記事の執筆ではなく、本文がある原稿の評価・推敲を対象にしています。

## できること

- 11基準・5層の評価により、減点根拠と修正方向を示す
- 論理、文のつながり、主述関係、反復、視点、読者との適合を点検する
- 根拠のある修正と表現の自然化を行い、元の意味や断定の強さを保つ
- 修正前後を比較し、旧指摘の解消と新しい違反を確認する
- 「評価だけ」「清書だけ」「最終本文のみ」などの指定に対応する

業界固有のルールは、入力で明示されたものを使います。別のスキルを自動で併用する必要はありません。

## 使い始める

1. このフォルダーを入手し、名前を `tsuzuri-fumiko` にします。
2. 利用先の公式手順に従い、`SKILL.md` と `references/` を含むフォルダー全体を取り込みます。
3. スキル一覧で名前を確認し、次のように原稿を渡します。

```text
tsuzuri-fumikoを使って、以下のブログ原稿を評価し、清書して修正確認まで行ってください。

【記事設定・制約】
読者：一般読者
文体：原稿に合わせる
SEO案・画像案：不要

【評価対象の原稿】
ここに原稿を貼り付ける

【参考資料】
必要に応じて出典と日付を記入する

【前回の評価結果・修正指示】
ある場合だけ、対象の版とともに記入する
```

依頼の例として、[架空の短い原稿](examples/sample-request.md)を用意しています。実在の顧客や案件を使った例ではありません。

この配布物は[Agent Skills仕様](https://agentskills.io/specification)の `SKILL.md` 形式に沿っています。取り込み先の保存場所、ZIP対応、呼び出し記号は製品の仕様に従ってください。すべての製品で動作確認したものではありません。

スキル機能のないAIでは、[v1.2のプロンプト全文](references/combined-prompt-v1.2.txt)を渡し、末尾の入力欄を埋めて使えます。そのAIが全文を読み込めるか確認してください。

## 出力を指定する

通常は、清書本文、要確認事項、重要な変更点、前後の全11項目の評価要約、文字数と未解決事項を返します。画像案・SEO案は依頼がある場合だけ追加します。

```text
評価・清書・修正確認を行い、最終回答は本文のみで返してください。
```

「本文のみ」は表示の指定です。評価や修正確認の工程は行います。工程自体を限定するときは「評価だけ」「清書だけ」と指定してください。

詳しい評価が必要なら、「初回と最終の評価を、根拠の引用と修正指示を含む7項目形式で示してください」と依頼できます。

## 評価と終了条件

文章品質の合格には、次の3条件すべてが必要です。

1. 合計97点以上／110点満点
2. 全11項目が8点以上
3. 8-a（主語交代・主述のねじれ）、8-b（係り受けの宙づり）、6-a（打ち消しの孤立）の検出がゼロ

文字数、指定条件、重要事項の確認、新しい問題の有無は別に判定します。明示の字数指定がなければ、入力本文比±5%が条件です。条件を満たせない場合は、理由と未達を示します。点数を上げるために事実を足したり、重要な主張を削ったりしません。

初回の評価・清書・再評価を行い、必要な場合だけ追加修正を1回行います。改善できない問題は未解消として残し、無限に書き直しません。

「公開候補」は文章品質の判定です。外部ファクトチェック、法務確認、社内承認の完了を意味しません。AIによる評価には見落としや揺れがあるため、公開前に重要な変更と確認事項を確認してください。

## 版と原本

- 動作基準：併用プロンプト v1.2
- 配布構成：revision 2

v1.2全文は、提供されたZIP内の内容をバイト単位で変更せず収録しています。`SKILL.md` にはライセンスへの参照だけを追加し、実行手順は変更していません。原本内の統合評価・AI清書がv1.0と表記されているのは、v1.2の併用運用規定がこの2本を組み合わせているためです。

原本のSHA-256は [SOURCE-SHA256.txt](SOURCE-SHA256.txt) にあります。改行変換でも値が変わるため、`.gitattributes` では原本の自動改行変換を無効にしています。配布ファイル全体のハッシュは `FILES-SHA256.txt` にあります（同ファイル自身を除く）。今回の変更範囲は [CHANGELOG.md](CHANGELOG.md) を参照してください。
